# Padrões de Desenvolvimento

> Convenções adotadas no projeto. **Provisório para validação** — se a equipe já tem um guia de
> estilo/lint, me apontem que eu alinho. Data: 2026-09-23.

Escrito para: quem vai programar no projeto.

---

## 1. Stack e versões

- **Python 3.12**, **FastAPI**, **SQLAlchemy 2** (estilo tipado), **Alembic**, **PostgreSQL 16**.
- **Frontend:** React + TypeScript (Vite).
- Ambiente de dev: **Docker Compose** (`infra/`). **Nunca** rodamos contra servidores reais em dev.

## 2. Estilo de código (Python)

- Formatação e lint com **Ruff** (`line-length = 100`, `target-version = py312`).
  Regras: `E, F, I, UP, B, C4, SIM, RUF`.
- Tipagem estática com **mypy strict** (`disallow_untyped_defs`). Tudo tipado.
- `from __future__ import annotations` no topo dos módulos.
- Nomes de domínio em **português** (ex.: `hash_senha`, `criar_access_token`, `usuario`), alinhados ao
  negócio e ao banco; termos técnicos consagrados podem ficar em inglês (`router`, `token`).
- Docstrings curtas em português explicando o "porquê".

## 3. Banco de dados

- `snake_case`; PKs `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- **Fonte da verdade** do schema: `database/schema.sql`. Toda mudança vira **migration Alembic**
  versionada **e** é refletida no `schema.sql`.
- Datas em `TIMESTAMPTZ`; flags em `BOOLEAN`.

## 4. Segurança (regras firmes)

- **Nenhuma credencial no código.** Segredos só via env/secrets (`SECRET_KEY`, `DATABASE_URL`,
  SMTP...). App falha ao iniciar se faltarem (fail-fast).
- `.env` **nunca** versionado (ver `.gitignore`); só `*.env.example`.
- Senha de usuário com **Argon2id** (`app/core/security.py`) — jamais texto puro (o legado guardava
  em `FONE2`; isso não se repete).
- **2FA por e-mail** e confirmação de cadastro (Fase 1).
- Containers rodam como **usuário sem privilégios** (não-root).
- Certificados A1 (`.pfx`) e suas senhas: **cifrados** em repouso; nunca em log.
- **Não alterar acessos/segurança em servidores** como parte do desenvolvimento — trabalho é local.

## 5. Organização da API

- Versionada em `/api/v1`. Routers por recurso em `app/api/v1/`, agregados em `router.py`.
- Dependencies compartilhadas em `app/api/deps.py` (sessão de banco, claims do token).
- Regras de negócio saem dos endpoints para serviços (`app/services/`) quando crescerem.
- Integração com o sistema comercial isolada atrás de um **gateway** (`DbGateway` hoje, `ApiGateway`
  depois) — ver `docs/01 §3.9`.

## 6. Testes

- **pytest** (+ `httpx` para a API). Testes em `backend/tests/`.
- Cobrir regras de segurança (hash, expiração de token, OTP) e migrações.

## 7. Git

- Branches curtas por tema; `main` protegida.
- Commits pequenos e descritivos (português). PR com descrição do que muda e por quê.
